# 两台 Windows 接力验收（临时小说）

本轮由用户远控第二台设备；不要求两台设备处于同一局域网。真实断网测试按用户要求暂缓。

## 安装与隐私

从项目 GitHub Release 下载本轮 Windows x64 测试安装包，在两台机器安装相同版本。
这是未签名的测试构建。发布内容不含作者的 NAS 地址、账号、API 密钥、小说或本机开发日志。
每台机器单独配置自己的模型连接，密钥不通过小说目录复制。

## 先验收正文接力

1. 使用 NAS 或网盘官方客户端、映射盘或挂载工具，让两台机器都能访问同一个**临时测试小说目录**。盘符、设备路径可以不同。
2. A 机打开该目录，新建 DOCX，输入“甲机第一轮。”，保存并退出。等待客户端完成同步/上传，再操作 B。
3. B 机在应用中打开相应目录，核对同一章节内容；追加“乙机第二轮。”，保存并退出，再等待同步完成。
4. A 机重新打开，核对两轮文字都存在。复制一段到普通文本框，确认段首是两个可复制的全角空格。
5. 记录两台机器版本、访问方式、是否收到冲突提示、能否用 Word/WPS 打开保存后的 DOCX；不需要提供公网地址、账号或密钥。

同步/挂载由服务商客户端提供；TCP 可达不代表文件同步完成。两台机器轮流操作，同步结束后再换机。

## 创作资料也要单独验收

正文目录与应用固定 `创作资料/<projectId>/` 是两处数据。**只同步正文文件夹不会自动同步人物卡、世界观、文风、讨论与摘要。**

当前可使用“备份本书/导出整本书 ZIP”携带正文和固定资料；从校验过的备份恢复到新目录，在另一套应用数据环境中打开，会导入资料。恢复不会覆盖已有资料或现有小说。

测试时可在 A 创建虚构人物卡和世界观后备份，用 B 的空测试环境恢复，核对资料与小说 ID。若 B 已有相同 ID 的目录，关闭旧目录或改用独立测试数据环境，避免错误地合并两个副本。

这一步验收的是完整备份迁移。固定资料的跨设备自动同步、实际 NAS/云盘联调仍待完成，不能将它记成已经实现的自动接力。
