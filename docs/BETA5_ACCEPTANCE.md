# beta.5 安装与正则功能验收

更新：2026-10-26，beta.5。以下人工步骤供两台Windows验收，不代表已在用户设备执行。

## 安装

两台电脑保存退出并保留整书/固定资料备份，下载同一Release的Windows x64测试包，核对`SHA256SUMS.txt`。不要先卸载旧版或删除创作资料；升级冲突时保留双方和备份，不清空目录绕过提示。模型配置与密钥由两端独立管理，不复制整个AppData。[安装保护](INSTALLER_SAFETY.md)和[两机接力步骤](SECOND_WINDOWS_ACCEPTANCE.md)继续适用。

## 社区导入与只读预览

使用一份单独的虚构测试小说，准备UTF-8 JSON文件：

```json
{
  "scriptName": "虚构测试规则",
  "findRegex": "/cat/gi",
  "replaceString": "猫",
  "placement": [2]
}
```

1. 正文页打开“宏与正则…”，选择“导入正则脚本…”，导入该文件。应识别“单条脚本”，显示1条、完整原始JSON路径和SHA-256。
2. 打开保留字段说明，`scriptName`和`placement`应列为只保留、不参与手工预览。这些字段仍完整存在于原始JSON，不代表已调度酒馆生命周期。
3. 角色名填“星澄”，测试文本填`{{char}} cat CAT`，点击“预览”。宏栏应为`星澄 cat CAT`，正则栏为`星澄 猫 猫`；正文和设定不变。
4. 复制原始JSON路径，在文件管理器核对本书`小说资料/正则导入原件/<UUID>/原始正则.json`及同目录`manifest.json`。源副本清单只证明原件备份，不是活动脚本成功标记；成功应以应用返回结果和活动脚本为准。
5. 将示例放进数组`[{...}]`或`{"scripts":[{...}]}`可分别验收批量/包装格式；原始选中文件应保持不变。替换前的活动脚本原raw保留在本书`小说资料/正则脚本历史/`。
6. 打开另一部同名虚构小说，确认脚本和导入报告独立；关闭重开后脚本仍可预览，旧报告不跨书沿用。取消原生选择器不生成新原件或改动活动脚本。

原件BOM、CRLF和未知字段保留由自动化逐字节验证。恶意回溯的超时、取消、界面/主进程持续响应、排队同步不阻塞取消，以及输出膨胀边界由隔离自动化测试覆盖，无需使用真实小说或收费模型。

## 上限与边界

输入20,000字符、输出各200,000字符，256脚本，查找8,192/替换32,768字符，trim每脚本128项、每项8,192字符；JSON及Worker请求各1MiB。超限、错书、未知目标版本、链接或保存期间变化会停止并保留原件，不能靠删除原资料绕过。完整参数见[隔离说明](REGEX_ISOLATION.md)和[社区格式说明](REGEX_IMPORT_043.md)。

本版仍是未签名测试版。既有DOCX/历史/Word副本操作见[beta.4验收](BETA4_ACCEPTANCE.md)。官方客户端负责实际上传/下载，应用不报告服务商云端同步完成；真实断网已按用户要求移出验收。
