# beta.2 安装与升级验收

日期：2026-10-23。新版安装包的发布和执行结果由本批交接记录确认；本页不把尚未执行的步骤记为通过。

## 安装前

1. 两台电脑先保存并退出旧版，并等待自己使用的同步客户端完成传输。
2. 保留整本书备份。旧 beta.1 的人物、世界观等还可能在安装目录旁的 `创作资料` 中；不要先卸载旧版或删除这个目录。新版将改为安装目录之外的固定资料位置，升级迁移失败时应保留原件并停止继续写作。
3. 下载同一版 Windows x64 安装包，核对 Release 的 SHA-256。发布包不包含作者的 NAS 地址、账号、API 密钥或小说；每台机器独立设置自己的模型连接。

## 升级后核对

使用临时虚构小说，不拿正在连载的原稿验收。

- 书架仍能打开原目录，正文和小说 ID 保留；人物卡、世界观及原有时间线等资料能读取。
- 新版固定资料位于本机应用数据目录的 `创作资料/<projectId>/`，Windows 默认 `%APPDATA%/novel-writer/创作资料/<projectId>/`；迁移后保留旧资料原件。迁移备份另保存在该应用数据目录的 `material-upgrade-backups`，不要自行清空。
- 模型设置仍可读取本机原有连接，密钥框保持隐藏。不要把本机 AppData 目录复制到其他电脑。
- 新建 DOCX 的默认字体为宋体五号，段首有两个可复制的全角空格；保存退出后再次打开确认文字保留。
- 在写作空间打开“固定资料同步…”，启用并立即同步。书内的“小说资料/创作资料同步”应随完整小说目录交接，不能只复制 DOCX。

## 两台 Windows 轮流写作

A 在临时书中新增世界观或人物卡，保存退出，再等待 NAS/网盘客户端完成目录传输。B 使用同一版打开收到的完整小说目录，核对正文与资料；续写一段并修改虚构资料，保存退出后再传回 A。出现冲突时，先核对两侧版本，明确选择后再同步。

固定资料同步是应用对书内快照的核对。外部客户端负责传输；应用不能报告官方客户端的远端同步进度。无需同一局域网。按用户要求不进行真实断网测试。

## 开发自动化的范围

`tests/packaged-upgrade-desktop.ts` 在独立临时 runtime 中复制旧版已知运行文件，使用独立 `--user-data-dir` 和独立 `LOCALAPPDATA`，不启用 `NOVEL_WRITER_TEST_DATA`。旧版产生虚构 DOCX、人物卡、世界观、旧名时间线和加密假模型凭据，再叠加新版运行文件，验证重开、迁移、原字节、密钥隔离与保存退出。

它不会运行安装器、替换用户安装、读取用户真实 AppData 或复制真实安装旁的资料。因此它证明隔离环境内的 packaged 启动和资料升级行为，不能单独代替 NSIS 升级/卸载钩子的执行验收，也不能代替真实双机或官方同步客户端联调。

运行入口：`node node_modules/tsx/dist/cli.mjs tests/packaged-upgrade-desktop.ts --new-exe <新版打包目录中的exe>`。仅 Windows；结果和截图写入 `.artifacts`，临时 runtime 保留供核对，不自动删除。

2026-10-23 执行结果：隔离 beta.1→beta.2 的 packaged 升级模拟通过，包含迁移备份逐字节校验与重复启动保留迁移回执；最终类型检查通过，实际查看同步完成页面。证据：`.artifacts/packaged-upgrade-035.log` 与 `.artifacts/packaged-upgrade-035-87f69183-3492-4578-8618-c37009e02317/result.json`、同目录截图。最初路径断言未考虑 Windows MSIX 的路径重定向而失败，改用 `fs.realpath` 后通过；没有修改生产代码掩盖失败。仍未执行实际安装器覆盖升级。
