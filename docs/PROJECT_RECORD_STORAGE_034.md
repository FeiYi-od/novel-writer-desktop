# 六类结构化资料的归属修复

2026-10-22 / 034。时间线、人物关系、人物状态、提示词库、蓝图、文风版本原先使用小说父目录 `创作资料/<类型>-<书名>.json`，同名书可能碰撞，读取未核对projectId；旧hash还遗漏ID、时间及部分内容。

现统一保存在本书 `小说资料/<类型>.json`，`schemaVersion:1`及projectId严格匹配，hash覆盖完整UTF-8文件，保存前再次核对、原件留历史。共享ProjectRecord负责普通路径/文件校验、链接拒绝、排他首次发布与同文件串行；六个Store保留各自业务校验。文风版本无实际变化时不重写。

首次读取发现旧位置时，只有版本/归属完全匹配才原字节复制到新位置，旧文件保留。备份/ZIP导出前也会排空六类资料迁移，避免未打开对应面板就漏带旧文件。错误ID、未知版本、坏JSON、无效UTF-8、链接都显式报错，不能当空文件覆写。已有新文件优先使用。若旧版同名文件已被其他书占用，需人工核对归属/历史后再迁移，不会猜测应属于哪本书。

这些是随书的结构化JSON资料，人物/世界观/文风等既有Markdown固定目录保持原位置。新路径随完整小说文件夹、整书备份与导出传递。

验证由project-record.test.ts、六套既有存储测试及时间线/关系/状态/提示词/蓝图/文风版本桌面脚本覆盖；仅用临时虚构作品。
